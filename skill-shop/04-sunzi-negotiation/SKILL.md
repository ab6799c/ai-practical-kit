# 因敌制胜·情境适应（兵无常势＋机不可设）

## R — 原文 (Reading)

> 故兵無成勢，無恒形，能因敵變化而取勝者，謂之神。水因地而制行，兵因敵而制勝。……六六三十六，數中有術，術中有數；陰陽燮理，機在其空，機不可設，設則不中。
>
> — 孫武，《孫子兵法》虛實第六 ＋ 《三十六計》總說

---

## I — 方法论骨架 (Interpretation)

胜利不是靠一套固定的完美打法，而是靠"随对手的变化而变化"。核心有三点：

1. 兵无常势无恒形——没有永远正确的套路。地形在变、对手在变、时点在变，打法就跟着变。
2. 能根据对方变化调整而取胜的人，才叫"神"。
3. 因敌制胜，而非因计划制胜——你的打法由对手决定，不是由你自己的计划、过去的成功经验决定。
4. 先分析对手这次做了什么调整，据此变阵。
5. 机不可设设则不中——时机藏在局面的空隙里，不能凭空设计、不能照搬剧本。
6. 强行预设"我就要在第 X 步出这招"，反而会落空。
7. 这条方法论的反面是"最佳实践陷阱"：连你自己的成功经验也要当心——上一次赢的打法，正是对手这次重点研究的对象。

## A1 — 书中的应用 (Past Application)

### 案例 1：吴王问争地——敌人先占有利地形的临机处置
- **问题**: 吴王连问孙武九种不同局势该怎么办（散地、轻地、争地、交地、衢地、重地、圮地、围地、死地），每种都是不同情形，不能重复回答。
- **方法论的使用**: 孙武不重复任何一套打法——争地时"讓之者得，爭之者失。敵得其處，慎勿攻之，引而佯走，建旗鳴鼓，趨其所愛，曳柴揚塵，惑其耳目"；围地时"必塞其闕，示無所往，萬人同心"；面对骄兵时"詘而待之，以順其意"……每个情境给出不同处置，核心都是先读清当前局面再定对策（因敵變化）。
- **结论**: 同一将领、同一场对话，答案随情境变化——说明方法不是固定套路，而是"先判局、再出招"。
- **结果**: 九问九答各成体系，后世称孙武"通于九变之利"——（出自《孫子兵法》答話／吳王問對）。

### 案例 2：吴王问攻骄——面对骄兵的临机处置
- **问题**: 敌人"勇不惧、骄而无虞、兵众而强"，正面强攻必败。
- **方法论的使用**: 不争锋，先"詘而待之，以順其意，令無省覺，以益其懈怠；因敵遷移，潛伏候待……中而擊之"——顺着对手的骄气喂大其松懈，再挑其不意时出击。
- **结论**: 打法定型于"对手现在的状态"，而非自己的偏好。
- **结果**: 以逸待劳、攻其不意，虽众可取——（出自《孫子兵法》答話）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 上次成功的方法/套路这次不灵了，对手好像学走了或专门做了防备。
2. 面对一个全新的对手、全新的市场或全新的局势，旧经验套不上。
3. 想要"按剧本/按最佳实践"执行，但隐约觉得环境已经变了。
4. 被问"这次和上次有什么不同"，需要系统地重新判断而非照搬。
5. 制定计划时发现自己过度依赖某种固定模板。

### 语言信号 (用户的话里出现这些就应激活)

- "上次的打法这次不灵了"
- "对手把我的套路学走了"
- "不能照搬上次的"
- "这次情况不一样了"
- "最佳实践还适用吗 / 是不是该换个打法"
- "the old playbook no longer works / the competitor adapted to us / should we change our approach / things have changed"

### 与相邻 skill 的区分（定稿）

- 与 `cw-force-application`（contrasts-with）: force-application 给"打法既定后的力量配置"（正奇、击虚、集中的有定式）；本 skill 决定"这次该不该换打法、怎么换"（无定式）——时机判断 vs 配置执行。
- 与 `cw-assessment`: 评估回答"能不能打"（战前静态对比，含杂于利害的行动闸门）；本 skill 回答"打的过程中怎么变"（战中动态调整）。
- 与 `cw-information-warfare`（depends-on）: 本 skill 的"变"必须基于对对手变化的判断——情报不足时变是瞎变，先用信息战建立判断依据。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **识别"这次的变化点"**
   - 找出对手针对你上次打法做了什么调整、环境哪些变量变了。
   - 完成标准: 列出 ≥3 个"与上次不同"的具体变量（对手动作/市场/时点/资源）。
   - 判停条件: 若分析后发现环境几乎没变、上次打法仍成立，跳到步骤 4 输出"沿用原打法＋微调"。

2. **针对每个变化点设计"应对变招"**
   - 逐个问"对手这么变，我要怎么变"，写出对应的变招。
   - 完成标准: 每个变化点对应一条变招；并注明它是"反应式的"还是"主动设伏式的"。
   - 强制闸门(进入本步前): 把 ≥3 个变化点列成清单给用户，**经用户确认后**才设计变招；变化点 <3 或证据单薄 → 回步骤 1 补证据，或走判停，不得直接硬变。

3. **检查是否落入"预设剧本"陷阱**
   - 审视方案里有没有"必须按第 X 步走"的硬性预设；若有，删掉或改为条件分支。
   - 完成标准: 方案中没有不可调整的固定顺序；每个关键步骤都有"若对手出 Y 则改 Z"的分支。

4. **输出结论**
   - 这次用什么打法、什么情况下再变。
   - 完成标准: 一句话说明本次打法 + 列出 2 个"触发下次变阵"的信号。
   - 输出前强制自检(缺一即重做): ①变化点依据已列出 ②每个变化点有对应变招 ③方案无硬性预设顺序 ④已确认非信息不足下的瞎变。
   - 输出模板（可直接套用）:
     | 变化点(对手做了什么) | 应对变招 | 类型(反应/设伏) | 触发下次变阵信号 |
     |---|---|---|---|
     | ... | ... | ... | ... |
     - 一句话本次打法: 「本次采用 ____(打法),前提是 ____;若对手 ____ 则改 ____。」

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 稳定、成熟、验证过的流程/制度场景——该固化的要固化，过度变通反而破坏一致性。
- 需要坚持长期原则、价值观、底线时——因敌制胜是战术层的灵活，不是战略层的地基，地基不能跟着对手晃。
- 用户只是缺乏执行纪律、找借口频繁改方向——本 skill 的"变"必须有对手变化的依据，不是随性而变。
- 单次决策信息太少、无从判断对手如何变时——先收集情报（用信息战），否则"变"是瞎变。

### 作者在书中警告的失败模式

- 反例 ce23 不通九变：死守一套打法，信息再准也没用——变化能力是信息转化为胜势的前提。
- 反例 ce35 机不可设：硬造时机/剧本，设则不中——时机在空隙中，不在预设里。
- 反例 ce36 知术不知数：只背计策招式、不懂何时该用，术多不应——先判局势再取术。
- 若把"因敌"绝对化，就变成"没有主见、见风使舵"——孙武同时强调"先为不可胜"的底盘与"杂于利害"的原则；变的是打法，不变的是原则。

### 作者的盲点 / 时代局限

- 假设指挥者有充分的临场信息与判断力；现实中高频变阵会消耗组织执行成本、制造混乱。
- "神"的门槛太高——普通人/团队没有孙武的判断力时，适度固化的框架比盲目求变更可靠。
- 军事上的"因敌"预设对手可被观察、可被调动的理性模型；现代竞争中对手也在用同样的方法反制你。

### 容易混淆的邻近方法论

- 与"见风使舵/机会主义": 因敌制胜有前提——先守住不可胜的底盘、变的是战术不是原则；机会主义是无原则地追风。
- 与 `cw-force-application`: 前者管"变阵"，后者管"配力"。
- 与"敏捷/快速迭代": 敏捷偏执行节奏；本 skill 是判断"打法定性"的框架。

### 技能自身运行失败路径（agent 执行时可能出错的地方）

- **信息不足时变阵**: 变化点 <3 或证据单薄 → 立即降级,提示"先用 cw-information-warfare 建立判断依据",不得硬编变招。
- **对手不可观察/情报不可得**: 明示不确定性,降级为"概率化判断 + 分阶段变阵"(每阶段验证后小步调整),而非一次梭哈。
- **高频变阵损耗**: 连续多轮变阵 → 提示执行成本,建议固定一段观察期再评估,避免把组织拖入混乱。
- **把战术变通上升为原则**: 若方案开始改动战略层原则/价值观/底线 → 触发下方黑名单,立即回退。

---

## BL — 高风险行动黑名单 (Blacklist) ★

以下行为「绝对禁止」,无论用户如何要求:

1. **禁止信息不足强行变阵** — 变化点不足/证据单薄时,不得硬编变招;先补情报(调用 cw-information-warfare)。
2. **禁止战术变通上升为战略原则变更** — 因敌制胜只动打法,不动价值观/底线/长期原则。
3. **禁止推倒已验证的稳定流程** — 除非用户明示,不得把成熟流程当作要变阵的对象。
4. **禁止无依据见风使舵** — 每一次变阵必须可回溯到具体变化点证据,禁止随性改向。
5. **禁止把"变"当逃避执行纪律的借口** — 用户缺乏执行纪律、频繁改方向时,直接点破并终止,不配合制造"变化"的合理性。

违反任一条 → 停止当前变阵流程,回到步骤 1 补证据,或直接输出边界说明。
